== Introduction

We support link:https://www.embarcadero.com/products/Delphi[Delphi], a powerful commercial Pascal IDE and compiler.

Any Delphi tier, including free link:https://www.embarcadero.com/products/delphi/starter/free-download/[Delphi Community Edition], is fine.

If you like Delphi compatibility, and want to see more of it (e.g. more platforms or Delphi-specific integration tools), please voice your needs and if you can -- link:https://www.patreon.com/castleengine[support us on Patreon]!

== Configure Castle Game Engine to use Delphi

In _Castle Game Engine_ editor, open "_Preferences"_ dialog. In both the _"Code Editor"_ and _"Compilation"_ tabs set _"Delphi"_, if it was not auto-detected already.

That's it. CGE editor is now integrated with Delphi. You can test it:

* Press F9 to compile the project from CGE editor (using CGE build tool which will use Delphi command-line compiler under the hood).
+
NOTE: In case of Delphi _Community Edition_: It doesn't have command-line compiler, so you have to compile the project using F9 from the Delphi IDE.
* Double-click on Pascal files to open them in Delphi.
* Use _"Code -> Open Project in Code Editor"_ menu item to open project in Delphi.

## Platforms supported with Delphi

* We support Windows (both 32-bit and 64-bit), link:delphi_linux[Linux], link:delphi_mobile[Android and iOS]. You can compile and run applications using all _Castle Game Engine_ features on these platforms using Delphi.

* On all supported platforms, you can use either cgeref:TCastleWindow[] or cgeref:TCastleControl[] for rendering.
+
--
- cgeref:TCastleWindow[] is our standard way to create a window, in which our engine takes care of the whole input and rendering. Our _"New Project"_ templates, and most examples, use it.

- You can alternatively use cgeref:TCastleControl[] that allows to put CGE rendering on FMX (FireMonkey) or VCL form. VCL is only for Windows, of course. link:control_on_form[See here for details].
+
To register the cgeref:TCastleControl[] component in Delphi IDE, follow link:delphi_packages[Delphi packages installation instructions].
--

* The only platform not fully supported with _Delphi_ is link:delphi_macos[macOS]. It is still supported _partially_:
+
Rendering on _macOS_ doesn't work, but basic units compile and 3D loading/processing works. You can test it with a command-line https://github.com/castle-engine/castle-engine/tree/master/examples/viewport_and_scenes/scene_information_cli_tool[scene_information_cli_tool] from our examples. It can be built and works as a command-line tool on macOS.

[#delphi_version]
## Delphi versions supported

The engine is tested and supported on Delphi versions listed below.

* They all include the free _Community Editions_ versions.

* We always recommend the latest Delphi version, and we support all platforms with it.

* We test both manually and automatically using continuous integration (link:ci[CI]). If we missed anything, if some example does not work as expected, please https://github.com/castle-engine/castle-engine/issues[report it].

Delphi versions supported:

Windows (32 and 64-bit):: Delphi >= 10.2.1 (or link:cpp_builder[{Cpp} Builder] >= 11.3).

link:delphi_linux[Linux]:: Delphi >= 11.3.

link:delphi_mobile[Android]:: Delphi >= 10.4.2 (link:delphi_mobile#delphi_version_why[read here why, and how you can bend this rule to go as far back as "10.4.0 with patch 1"]).

link:delphi_mobile[iOS]:: Delphi >= 13.1 (link:delphi_mobile#delphi_version_why[read here why, and how you can bend this rule to go as far back as "10.4.2"]).

link:delphi_macos[macOS]:: Delphi >= 13.1 (same reasons as iOS).

[NOTE]
====
Older Delphi versions didn't support _"project welcome page in a Markdown format"_. And most of our examples use this feature, to show a nice `README.md` of the project when you open it in a newer Delphi version.

This causes harmless warnings when opening our examples in older Delphi versions, like 10.x -- upon opening the DPROJ, it will propose to open `README.md` in a default associated Windows application, like a text editor. Just ignore the dialog about `README.md` and Markdown, the project will still work correctly.
====

[#delphi_version_why]
### Why these Delphi versions? Can we support older Delphi version for some platforms?

In general: the answer is always _"maybe, let's talk"_, and it never hurts to https://castle-engine.io/talk.php[ask us] :) If you have a strong use-case, e.g. an existing cool project and it is really impossible to upgrade the Delphi version -- contact us, tell us about it.

That said, we did research for each of the requirements above, so it's not easy.

* link:delphi_mobile#delphi_version_why[Reasons behind our minimal Android and iOS Delphi versions].

* https://github.com/castle-engine/castle-engine/issues/577#issuecomment-2027060068[This GitHub issue documents reasons behind our minimal support for Linux].

* For Windows, it could be possible to push the minimal supported Delphi version further down, although it gets more and more painful to maintain:) See link:https://github.com/castle-engine/castle-engine/issues/482[XE7 test], link:https://github.com/castle-engine/castle-engine/issues/486[10.0.1 test], link:https://github.com/castle-engine/castle-engine/issues/488[10.1.2 test].
